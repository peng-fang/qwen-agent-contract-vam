# 我们下一步先做什么

更新：2026-11-14。这里只定下一轮，不表示实验已经执行。项目协作统一使用 [Markdown 任务清单](../../docs/PROJECT_TASKS.md)，研究分支为 `research/evidence-budget`，共享 main 不变。

## 下一轮的唯一目标

**先判断本机 qwen2.5:7b 能不能根据日志里的关键条件，选对不同的补丁。**

现有 1B 模型连完整日志也表现不稳定。继续扩大压缩算法比较，会把模型没理解题目和压缩丢了信息混在一起。先沿用 Agent Budget Lab 的小实验诊断；这一轮不接完整合同 RAG，也不接手组内全部基础功能。

## 一轮规模

| 项目 | 固定设置 |
|---|---|
| 任务 | 已有 6 道开发题，共 3 对；四道预留题保持不运行 |
| 模型 | 先确认本机现有 qwen2.5:7b 可用，记录实际权重 digest |
| 输入 | 完整日志、无日志两组 |
| 重查 | 0 次，先隔离单步理解能力 |
| 重复 | 两轮配对种子；沿用既有“重复会改变选项顺序与背景”的定义 |
| 规模 | 6 题 × 2 种输入 × 2 轮 = 24 条实验；正常完成时每条一次模型调用 |
| 固定部分 | 沿用 diagnostic-v3，不因希望某种方法获胜而中途改题或挑选结果 |

执行前检查模型是否已安装、服务是否正常；本轮不自动下载更大模型或调用收费 API。切换模型使用单次运行环境，不修改两边仓库的默认模型配置。

## 记录与判断

- 保存实际提示、全部响应、最终补丁、逐题验收、成对全对、协议错误、服务报告的输入/输出 token 和耗时。
- token 未报告则记 null；冷启动另标，不把局部检索计数或框架的占位 0 当实际总用量。
- 人工看至少一组成功和一组失败（若存在），区分条件理解错、忽略证据、选项理解错和输出协议失败。
- 暂定继续门槛：三对开发任务中，至少两对在两轮都能用完整日志答对，并且没有未解释的协议问题。这是工程筛选门槛，不是统计显著性或泛化结论。
- 若无日志与完整日志效果接近，检查是否靠选项常识、猜测或其他泄漏；不能直接声称日志没有价值。

## 看到结果后再分支

**完整日志仍不可靠：**先写失败分析，定位题目/提示/协议/模型能力。若改协议，升版本并重新跑对照；当前阶段暂停压缩方法排名。

**完整日志能可靠使用条件：**再准备两对短合同证据任务，先做“是否符合退款条件”和“手续费基数”两族。只改变关键条件，固定证据片段；用 Qwen-Agent 的 knowledge 入口与只读证据查询做最小适配。

**实际材料太短，没有压缩需求：**保留这个结果。优先考虑 [路线 C：用户更改条件后的选择性重算](ARCHITECTURE.md)，例如课时从 8 改为 13 后，旧资格判断和退款计算是否及时失效。

预算分配策略（路线 B）等任务、验收和工具接口可靠之后再做。
