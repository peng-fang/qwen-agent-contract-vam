#### 3.5.2 自定义合同 MCP server

新增 `mcp_servers/contract_tools.py`，暴露：

- `calculate_refund(total_paid, used_sessions, list_price_per_session, refund_fee_rate)`
- `calculate_total_cost(annual_fee, years, ...)`

**第一次启动报错**

```text
TypeError: issubclass() arg 1 must be a class
```

**原因**

脚本使用了 `from __future__ import annotations`，FastMCP 1.12.4 在解析类型注解时拿到字符串，直接调用 `issubclass` 导致崩溃。

**修复**

删除 `from __future__ import annotations`，使用运行时真实类型注解。

**第二次报错**

直接调用 Qwen-Agent 的 MCP 工具时：

```text
TypeError: the JSON object must be str, bytes or bytearray, not dict
```

**原因**

MCP 工具 wrapper 的 `call` 要求 JSON 字符串，不像普通 `BaseTool` 可接受 dict。

**修复**

```python
tool.call(json.dumps({...}, ensure_ascii=False))
```

**验证结果**

```json
{
  "total_paid": 4800.0,
  "used_sessions": 8,
  "list_price_per_session": 300.0,
  "used_value_at_list_price": 2400.0,
  "remaining_before_fee": 2400.0,
  "refund_fee": 480.0,
  "refund_amount": 1920.0,
  "consumer_loss": 2880.0
}
```

模型自动调用该工具并回答“可退 1920 元”。

## 6. 关键质量发现：页码引用不可靠

这是本次验证最值得写进课程报告的一点。

- 合同实际只有 2 页，退费条款在第 1 页。
- 模型回答“合同条款：页码 4”。
- 它引用的原文是正确的，但页码是错的。

原因不是 PDF 解析失败，而是：

1. Qwen-Agent 的分块文本中即使带 `[page: N]`，最终仍由模型自由生成引用；
2. 7B 模型没有“只能从上下文复制页码”的强约束；
3. 当前应用没有对页码做后处理校验。

**课程项目的正确做法**

- 不要让模型“生成页码”，让检索层返回结构化 `evidence_id`；
- 抽取阶段保存 `file_name`、`page`、`char_start`、`char_end`、`bbox`、`quote`；
- 模型只输出 `evidence_id` 和判定；
- UI 用 `evidence_id` 反查原文并高亮；
- 增加“页码必须在文档页数范围内”的自动校验。

这也说明：**“合同聊天”不难，难的是可核验的证据链。**

| 本地 32B Q4 | 24GB VRAM、64GB RAM | 48GB VRAM | 课程作业一般不需要 |
| OCR 扩展 | CPU 可跑 | GPU 更快 | 扫描件 PDF 需要额外 OCR，当前未做 |

**结论**：如果只做课堂演示，本机足够；如果要让 5 类条款的判断稳定，建议用 API 模型（qwen-plus/qwen-max）或 14B 以上本地模型。7B 适合验证链路，不适合追求准确率。

## 10. 是否适合作为 NLP 课程 Agent 项目

### 结论：适合，而且题目选得好

优点：

1. **不是纯 prompt demo**：有跨文档匹配、证据检索、数值工具、证据不足追问。
2. **可量化**：条款抽取 F1、矛盾分类 Macro-F1、证据定位准确率、计算正确率。
3. **可消融**：去掉 RAG、去掉跨文档匹配、去掉计算工具、换模型，都能做对照。
4. **演示效果好**：上传两份 PDF → 标红矛盾 → 输入上课次数 → 算损失 → 点证据回原文。
5. **有真实痛点**：健身、培训、租房合同里的宣传承诺与合同条款不一致很常见。

需要提前规避的坑：

- 不要做“违法判定”，只做“宣传与合同是否一致 + 需核实问题”。
- 不要一上来做全行业，先做健身房或培训之一。
- 不要只做 5 类条款的开放域聊天，要做**固定 schema + 证据 ID**。
- 不要用模型生成页码，页码必须来自解析层。
- 不要只报一个总准确率，要分“抽取/匹配/证据/计算”四项指标。

### 建议的课程 MVP

- 场景：健身房合同。
- 输入：宣传 PDF + 合同 PDF（可提取文本）。
- 条款：退款、违约金、自动续费、服务期限、额外收费。
- 输出：
  1. 五类条款对照表（一致/矛盾/证据不足）；
  2. 每条的证据：文件名、页码、原文短句；
  3. 金额计算：退款/总成本；
  4. 签约前问题清单。
- 数据：100–150 组，建议 60 组矛盾、40 组一致、30 组证据不足、20 组计算题。
- 基线：关键词/BM25 + 规则。
- 消融：无 RAG、无跨文档匹配、无计算工具、7B vs API 模型。
- 演示：本次 `ui_answer.png` + `ui_calc2.png` 的流程即可。

## 13. 最终判断

**可以跑，且值得做。**

Qwen-Agent 已经把“文档上传 + RAG + 工具调用 + Web UI”这条链路铺好，本次在普通 6GB 显卡笔记本上完整跑通，说明课程项目的技术可行性成立。

但本次也暴露了真正的难点：**模型会编页码，7B 的判断和格式遵循都不稳**。所以项目重心不应放在“接一个模型聊天”，而应放在：

1. 条款结构化抽取；
2. 页码/原文/证据 ID；
3. 确定性的跨文档匹配；
4. 可验证的计算工具；
5. 100–150 组标注与分项评测。

只要把“证据链”做成工程件，而不是让模型自由发挥，这个题目就具备一门 NLP 课程作业应有的深度和演示效果。

该合同的金额核对结论（详细版见对话回复）：

- 月租 7,150 × 12 = 85,800，算术一致；
- 押金 14,300 = 2 个月租金；
- 若押金与租金分开，首期是 100,100，不是正文单独出现的 85,800；
- 租期写成 12 个月，但 2026-08-15 至 2027-08-10 实际是 360 天，少 5 天；
- 电费 2 港币/kWh、年上限 1,500 港币，折合每年仅 750 kWh，超出部分从押金扣；
- 支付渠道费 0%–5.5%，最高可多付约 5,491 港币；
- 租客提前退租被禁止，押金可被没收，且合同保留追讨余下租期租金的权利。

同时确认：**两份无关合同一起上传会互相干扰检索**。演示时建议一次只上传一份合同，宣传材料另开一轮。

## 15. 追加功能：合同情景推演与决策评分（2026-11-12 21:25）

> 历史记录：本节描述的是当时的 Gradio 版本，后迁移到 React 前端。自 `#14` 起导航不再提供推演页面，`/api/vam/*` 与 `vam_sandbox/` 仅作为后端接口和测试保留，主流程改为条款核验 + 签约前清单。
> 当前实现是**同一模型的两个角色提示**（发散 / 打分），不是两个独立 Agent；当前口径以 `README_DEMO.md` 为准。

按“两段式角色提示（发散 + 打分）”思路，在 Qwen-Agent 里新增了合同情景推演与决策评分模块：

- **发散角色提示**：生成最多 2 层、第一层 3 个主分支的情景树，区分“事实 / 假设 / 不确定因素”。
- **打分角色提示**：给每个叶子情景打分（违约风险、可行性、预期损失），Python 按固定权重算总分并排序；子分数缺失时总分为「信息不足」。
- **前端**：Gradio 5 + `gr.HTML`，用原生 `<details>` 渲染可展开决策树，颜色区分风险等级，点击节点看事件/风险/理由。
- **入口**：`examples/assistant_vam_sandbox.py`，端口 7861；启动脚本 `start_vam_demo.ps1`。
- **设计取舍**：没有用自由 Group Chat，而是“先发散、后收敛”的两段式调用，目的是稳定拿结构化 JSON、控制分支数量、避免多轮角色对话失控。
- **交互**：支持“沿此分支继续推演”（多推一层）、“回溯一步”（回上一棵树对比）、导出 Markdown 报告。
- **入口联动**：合同核验页右上角新增「打开合同情景推演与决策评分」按钮，点击在新标签页打开 <http://127.0.0.1:7861>。

验证结果（示例：融资 1000 万、3 年净利润对赌 3000 万）：

| 排名 | 分支 | 总分 | 风险 | 概率 |
| --- | --- | ---: | ---: | ---: |
| 1 | 达成对赌条件 | 82.0 | 2.0 | 0.70 |
| 2 | 中性/意外情况 | 56.0 | 4.0 | 0.30 |
| 3 | 未达成 → 年化 8% 回购 | 53.5 | 6.0 | 0.40 |
| 4 | 未达成 → 股权补偿 | 51.5 | 5.0 | 0.30 |

该模块定位是“情景推演沙盘”，不是真实预测；结果已在前端明确标注“仅供参考”。
