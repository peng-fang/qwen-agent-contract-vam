# 四项合同工作流：运行、边界与验收

基线为 main 的 `359ffe5`。保留原规则核验、单合同 Judge、证据注册表和原有四个页面，在功能分支增加报告追问、参数续办、付款计划与语义复核。

## 使用入口

1. **合同核验 → 风险审查 → 带着问题问助手**：审查生成服务器报告快照。追问自动关联风险顺序、法域、条款、法律依据和最近8轮历史；关闭再打开会恢复对话。引用可展开查看。新合同/新报告使用独立会话。
2. **宣传 vs 合同 → 补充事实与模型复核**：填写已上课节数、实付、每节原价、申请天数或申请阶段，再点击“确认事实并继续核验”。用户事实独立保存，不写入合同原文；再次修改后计算新版本，并使旧模型复核失效。可“恢复最近一次核验”。
3. **付款计划与现金流**：手动编辑两份计划，或上传合同提取草稿；未知日期/金额留空。逐期核对并勾选确认后保存计算，得到精确时间表与累计支出阶梯曲线。编辑后明确提示下方仍为旧版本结果。按同一币种、同一付款方比较，不自动换汇。参考原文与用户编辑来源分别标注。
4. **宣传 vs 合同 → 模型复核当前结论**：在规则结果之后显式调用复核角色。检查时段、主体、条件和例外，保留规则结论并显示复核后结论；统计和风险评分随复核更新。改变结论的金额先清空，等待条件确认。调用失败、缺失项目或伪造引用时不应用任何意见。

## 模型配置与密钥

新增模型调用统一在 `backend/app/services/workflow_llm.py`，提示词保留在各功能模块并记录版本，不向网页暴露密钥。

- `WORKFLOW_MODEL_PROVIDER=auto`：优先使用已有 OpenAI 配置；没有时沿用 Qwen-Agent。
- `openai`：Python OpenAI SDK Responses API，保留 `Accept-Encoding: gzip, deflate`、70秒超时及一次重试。
- `qwen`：使用项目既有 `get_chat_model` 和 `default_llm_cfg`，无本地模型时需要配置已有远程 Qwen 服务。
- OpenAI 密钥优先从环境变量 `OPENAI_API_KEY` 读取；然后引用仓库同级 `course_agent/local_key.py` 的 `load_key('openai')`。无需复制加密文件，需要同一 Windows 用户。
- `WORKFLOW_MODEL` 优先于 `OPENAI_MODEL`；默认 `gpt-6-luna`，账户实际可用性须实测。
- 初始风险审查可设置 `REVIEW_MODEL_PROVIDER=openai`；未设置时原来 Ollama 行为保留。原通用“上传材料与提问”入口仍使用原 Qwen-Agent/MCP 配置；新增报告追问独立接入 Responses。
- 自定义 `WORKFLOW_API_BASE` 必须使用专用 `WORKFLOW_API_KEY`，共享密钥不转发到自定义地址。

本机已经在忽略的 `backend/.env` 设置 OpenAI 工作流与审查桥接，并关闭 Ollama 自动启动和预热。提交给其他同学的是配置示例，不含密钥或本机运行数据。

## 启动

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8017
```

打开 `http://127.0.0.1:8017/`。也可使用现有 `start.ps1`。新机器没有同级课表项目时设置自己的后端环境变量。

## 数据与接口

运行数据保存在忽略的 `backend/workspace/workflows/`，包括报告、会话、核验任务和付款计划。JSON 原子替换，进程内锁及乐观版本校验；旧版本提交返回409。适用于当前单进程本地服务，不构成多进程数据库或账号隔离系统。

新增接口统一在 `/api/workflows`：

| 接口 | 用途 |
| --- | --- |
| `POST /conversations` | 用报告ID创建会话 |
| `GET /conversations/{id}` | 恢复消息 |
| `POST /conversations/{id}/messages` | 追问；携带当前版本与风险ID |
| `GET /verifications/{id}` | 恢复原材料、事实与结果 |
| `POST /verifications/{id}/facts` | 补充确认事实并更新结果 |
| `POST /verifications/{id}/review` | 模型语义复核 |
| `POST /payment-draft` | 上传合同提取未确认草稿 |
| `POST /payments` | 确认、保存及计算付款计划 |
| `GET /payments/{id}` | 恢复计划及历史版本 |

报告快照在流式接口清理临时上传之前生成，追问不依赖临时文件仍存在。付款历史保留最近20个版本；合同草稿引用通过原文编号还原，无法验证编号时拒绝草稿。

## 验收

```powershell
$env:AUTO_START_OLLAMA='0'
$env:MODEL_PRELOAD='0'
$env:LEGAL_WEB_SEARCH_ENABLED='0'
.\.venv\Scripts\python.exe -m pytest -q
cd frontend
npm run lint
npm run build
cd ..
# 以下命令实际调用模型，使用虚构合同。
.\.venv\Scripts\python.exe -X utf8 scripts/accept_contract_workflows.py --live
```

自动测试覆盖参数缺失/更正、超过退款上限、阶段与期限不满足、用户事实来源、旧复核失效、会话恢复及引用、并发版本冲突、无效编号、负数/多余小数、日期、币种/主体混用和未确认计划。原80项回归保留。

真实 API 验收覆盖不同阶段收费的误报修正、同阶段真实矛盾保留、远程初始风险报告、连续报告追问、付款日期金额提取。响应及模型用量保存在忽略的 `.venv/review_artifacts/live_acceptance/results.json`，不输出密钥。

### 手工操作检查

- 报告追问两轮后关闭再打开，历史仍在；另一份报告不能引用前一份的风险ID。
- “学费4800元、每节300元、超过12节不退、手续费为实付20%”样例：补充8节时沿用原计算口径得到1440元；13节时返回不适用，不给单一金额。手续费基数不同的合同需要另行确认，不等同于现有 MCP 另一种基数的公式。
- 修改事实后旧语义意见消失；复核失败时规则结果仍在。
- 一次付清12000元与三期各4000元，最终均为12000元，中间累计分别不同；未确认或日期非法时不能保存计算。
- 草稿中相对日期缺起点时留空，用户补全确认后才计算。

## 当前限制

- 金额续办仍覆盖现有规则支持的退款条件；同时包含多个申请阶段时要求分开确认规则，不混算为一个金额。
- 模型引用ID校验保证来源可回查，语义是否正确仍需独立标注集验证。本次真实样例属于功能验收，不是泛化准确率。
- 当前真实模型验收使用 `gpt-6-luna`；切换其他模型后应重跑同一测试。Qwen 路径保留，但本机未部署本地模型，未做本地推理验收。
- 浏览器已观察到付款计划表格和累计曲线正确显示；文件选择自动化中断，因此上传到追问/补参/复核的完整页面点击链未全部验证。对应上传、恢复、更新及模型调用已经通过接口端到端测试。
